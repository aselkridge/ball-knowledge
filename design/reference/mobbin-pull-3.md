# Mobbin reference pull 3 · 2026-08-25

Pulled for the design-bible decision board (item 111), after Aaron asked
for examples per decision, not explanations. Two targeted questions this
time: how do the best dark UIs light exactly one action (feeds D1), and
how does sports design use condensed type (feeds D5/D8). Same law as
pulls 1 and 2: LINKS and READINGS, not copies, each reading mapped to OUR
surface.

## Pull A · one lit action on a dark ground (feeds D1, the lit-means law)

- **Life Reset, onboarding** · <https://mobbin.com/screens/db2bc2ba-38a4-45cf-97a1-05dc78be1030>
  Near-black screen, ONE saturated button, everything else in two greys.
  The choice reads instantly because there is exactly one lit thing. This
  is the pattern our league picker should follow: the two live leagues
  lit, the five coming-soon ghosted, no third state.

- **Xbox, console picker** · <https://mobbin.com/screens/991f06d2-49dd-4e4d-a273-58ede394ee20>
  Selection told by a bright ring + fill on the chosen card while the
  others sit dim but readable. Selected and available-but-not-selected
  are DIFFERENT states from disabled; Xbox never confuses them. Our
  settings rows and setup cards need that same three-way honesty.

- **Opal, focus states** · <https://mobbin.com/screens/9ce6b9eb-88cb-49bd-b62b-6f68724ba0ee>
  Premium restraint: the active state is barely more than a lit border
  and a nudge of saturation, and it still reads. Proof that "lit" does
  not need glow or motion; contrast discipline does the work.

- **Breathwrk, session start** · lit primary against dim options; the
  CTA is the only saturated object on screen. Same lesson at a smaller
  scale: even a utility sheet keeps one lit action.

- **(Not Boring) Camera + Open** · both light the single primary with
  material colour and leave chrome monochrome. The chrome/content split
  our HUD already follows, confirmed twice more.

Reading for D1: the field is unanimous. Dark ground, one saturated
action, states told by light (lit = tappable now, dim = exists but not
now, ghost = coming). No screen in the set uses a disabled treatment
that could be mistaken for selected.

## Pull B · condensed sports type in the wild (feeds D5 type scale, D8 faces)

- **NBA app, game recap** · <https://mobbin.com/screens/a76ae8e4-816e-40db-92b5-06526efedbcf>
  Giant condensed numerals for the score, small tabular type for
  everything else, almost no middle sizes. Two-tier scale: HUGE and
  small. Our nine font sizes on one screen fail this test today.

- **Fixtured, fixtures list** · <https://mobbin.com/screens/0826f20f-586e-4a92-a913-6c4738963b26>
  Condensed caps for team names at list size and it stays legible;
  condensed is not just a headline face when the tracking is right.
  Reference for how far Anton (or a bought Druk) can be pushed down.

- **MLS, match header** · <https://mobbin.com/screens/42dcf496-6f10-4d38-8c1e-0e8a5d55e30f>
  Condensed display for the clubs, a grotesk for the meta line, mono for
  the clock. THREE faces with jobs, no drift. Exactly our intended trio
  (display / Archivo / Space Mono), used with discipline we don't have
  yet.

Reading for D5/D8: real sports products run two type tiers and three
faces maximum. The bible's job is to cut our 89 distinct font sizes to a
ruled ladder, and D8 decides which display face anchors it.

## What the pull changes

- D1 (lit-means law) now has a five-product evidence bar behind it, so
  the ruling is a choice between renderings, not a leap of faith.
- D5/D8 get a measurable target: two type tiers on a screen, three faces
  in the product.
- All readings are embedded beside their rendered options on the
  decision board, so the evidence and the choice sit on one page.
